# 曼格云公众号采集

用户只需说公众号名称、最近篇数或日期范围。不要让用户处理 `ghid`、`collectionId`、页码、游标、SQLite 或命令行。

此技能只调用曼格云 `https://api.we-media.cn`。凭据仅使用 `WE_MEDIA_API_KEY`；不要回显、记录或提交 API Key。

## 首次使用

先执行脚本的 `status --verify`。未配置时读取 [第一次使用](references/first-use.md)，一次只引导一步。不要因为用户曾在对话中粘贴过密钥，就擅自把它写入文件。

## 默认行为

- 用户只给公众号名称：默认获取最近 1 篇纯文本正文。
- 用户说“最近 N 篇”：取按发布时间排序的最近 N 篇正文。
- 用户给日期或年份：先采目录并保存断点，再准确计算缺失正文数；正文另行确认。
- 用户说“全部历史”：分批顺序采目录，默认每轮最多 10 页；只有 `hasMore=false` 才算目录完整。
- 用户给文章链接且只要单篇正文：不使用本技能的名称搜索/历史流程，按曼格云文章正文契约直接处理。

具体商品、字段和分页约束见 [曼格云接口映射](references/mangge-api.md)。

## 费用门禁

任何费用展示或预估前，都先运行脚本 `collect --dry-run` 查询实时产品目录。将脚本返回的 `estimated_max_cost_yuan` 用大白话告诉用户，并等待明确确认。

用户确认后，使用相同范围运行 `collect --confirm-paid --max-cost <已确认金额>`。脚本会再次查询实时目录；若价格上涨或范围超过上限，会在收费调用前停止。

不要硬编码价格。最终金额以脚本汇总的实际 `consumption`/`X-Charge-Micros` 为准。

## 名称解析

名称未缓存时，需要一次“搜一搜公众号”调用。若只有一个名称完全匹配且标识可用于历史接口，脚本自动保存选择；否则返回少量候选。

向用户只展示候选编号、名称、简介、微信号/别名和认证主体，不展示内部账号标识。用户选择后，用 `--candidate <编号>` 继续；脚本使用已缓存的搜索结果，不重复购买搜索。

## 最近文章

用脚本 `collect --account <名称> --recent <N>`：

1. 先 `--dry-run` 报本轮最高费用。
2. 确认后加入 `--confirm-paid --max-cost`。
3. 默认输出纯文本正文，不采互动、评论或图片。
4. 已归档正文不重复购买；最近列表仍会刷新第一页以发现新文章。

## 日期范围与全部历史

分两阶段执行，避免在文章数未知时一次授权大量正文费用：

1. 目录阶段：使用 `--metadata-only --max-pages 10`（或用户批准的页数），按返回的 `nextPage` 和原 `collectionId` 顺序续采。预算或页数用尽时必须报告 `partial`，保留断点。
2. 正文阶段：目录达到目标日期或 `hasMore=false` 后，再次 `--dry-run`。脚本按本地缺失正文数给出准确上限；获得确认后移除 `--metadata-only` 获取正文。

日期按北京时间闭区间理解。不要用“本页不足 20 篇”判断结束，也不要冷跳页或混用游标模式。

## 执行与完成

脚本入口：`scripts/mangge_wechat.py`。默认归档到当前目录的 `output/mangge-wechat/<公众号>/`，其中正文为 Markdown，另有索引和本地断点数据库。

完成时只告诉用户：状态、采到几篇、实际花费、保存位置、是否还有下一批。发生网络结果不明、预算耗尽、重复页或接口错误时报告 `partial`，不得声称完整，也不得泄露 API Key、内部游标或采集任务编号。
